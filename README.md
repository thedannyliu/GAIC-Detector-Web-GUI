# GAIC Detector Web GUI

[![Python](https://img.shields.io/badge/python-3.10-green)](https://www.python.org/)
[![AIDE](https://img.shields.io/badge/AIDE-ICLR%202025-red)](https://arxiv.org/abs/2406.19435)

GAIC Detector is a web application for AI-generated image/video screening.
The current implementation uses a single detector: **AIDE** (ICLR 2025), with Grad-CAM overlays and optional Gemini-generated narrative reports.

## What to review

This project turns a pretrained detector into an image/video screening workflow: upload validation, frame sampling, model scoring, Grad-CAM overlays, and optional language-model reports. The contribution here is the application and integration layer. The detector architecture and pretrained weights come from [AIDE](docs/MODEL_SOURCES.md).

| Engineering component | Implementation |
| --- | --- |
| Typed image/video API and structured failures | [`app/main.py`](app/main.py), [`app/errors.py`](app/errors.py) |
| Model loading and artifact-branch Grad-CAM | [`app/aide_inference.py`](app/aide_inference.py) |
| Video sampling and highest-scoring-frame selection | [`app/video_utils.py`](app/video_utils.py), [`app/main.py`](app/main.py) |
| Optional Gemini report with template fallback | [`app/report.py`](app/report.py) |
| Interactive upload, results, and session history | [`gradio_app.py`](gradio_app.py) |
| Weight-free API regression tests | [`tests/test_api_contract.py`](tests/test_api_contract.py) |

### Try the API contract without model weights

```bash
git clone https://github.com/thedannyliu/GAIC-Detector-Web-GUI.git
cd GAIC-Detector-Web-GUI
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-test.txt
python -m unittest discover -s tests -v
```

These tests exercise real HTTP handlers and image preprocessing with stubbed detector outputs. They verify that model failures return errors instead of a fabricated 50/100 score, invalid images are rejected, and partially failed video runs expose their missing frames. They do not measure detector accuracy or throughput.

### Evaluation status

This is a research/demo application. No held-out detection benchmark is committed here. The current wrapper repeats the resized image across AIDE's four ResNet input slots rather than reproducing the upstream patch-selection procedure, so upstream paper accuracy must not be attributed to this application. Grad-CAM shows one branch's contribution; it is not proof that a region was generated by AI. The 0–100 score is an uncalibrated model score, and taking the maximum across sampled video frames changes its statistical interpretation.

Before presenting detection-quality claims, validate the preprocessing against upstream AIDE and publish a held-out evaluation with video-level data splits. The [model fine-tuning repository](https://github.com/thedannyliu/GAIC-Detector-Model) is a related training project; this GUI currently loads the checkpoint described below.

## Current Scope

- Backend: FastAPI (`app/main.py`)
- Frontend: Gradio (`gradio_app.py`)
- Model: AIDE only (`models/weights/GenImage_train.pth`)
- Media types:
  - Image: `jpg`, `jpeg`, `png`, `webp` (max 10 MB)
  - Video: `mp4`, `mov`, `webm` (max 50 MB, max 300 seconds)

## Requirements

- Python 3.10
- Linux/macOS (Linux recommended for GPU workloads)
- NVIDIA GPU + CUDA for practical throughput (CPU mode works but is slow)
- 8 GB+ RAM
- 4 GB+ free disk for model weights and temp files

## Installation

1. Clone repository

```bash
git clone https://github.com/thedannyliu/GAIC-Detector-Web-GUI.git
cd GAIC-Detector-Web-GUI
```

2. Create environment

```bash
conda create -n gaic-detector python=3.10 -y
conda activate gaic-detector
```

3. Install PyTorch (match your CUDA version)

```bash
# Example: CUDA 12.1
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu121
```

4. Install remaining dependencies

```bash
pip install -r requirements.txt
```

5. Download AIDE checkpoint

```bash
bash download_aide_weights.sh
```

Expected path:

```text
models/weights/GenImage_train.pth
```

## Environment Configuration

Create `.env` from template:

```bash
cp .env.example .env
```

Common variables:

- `GEMINI_API_KEY`: enables Gemini reports when set
- `API_HOST`, `API_PORT`: FastAPI bind host/port
- `GAIC_BACKEND_URL`: frontend target backend URL
- `GRADIO_SHARE`: Gradio share mode flag

Important behavior:

- `submit_job.sh` **does** load `.env` automatically.
- `start.sh` **does not** load `.env` automatically.
- `start.sh` respects `GRADIO_SHARE` and defaults to `false`. Set it to `true` explicitly for a public demo link.

If you need custom env vars for local runs via `start.sh`, preload them in shell:

```bash
set -a
source .env
set +a
bash start.sh
```

## API Summary

Swagger docs:

- `http://localhost:8000/docs`

Endpoints:

- `GET /`: health check
- `GET /models`: model metadata (AIDE only)
- `POST /analyze/image`
- `POST /analyze/video`

Image response fields include:

- `score` (0-100)
- `model`
- `heatmap_png_b64` (optional)
- `report_md`
- `inference_ms`
- `errors` (non-fatal issues/fallback markers)

Video response adds:

- `key_frame_index`
- `key_frame_ts`
- `key_frame_png_b64`

Model failures return structured HTTP errors; they do not produce a neutral score. Partial video failures appear in `errors` as `FRAME_<index>_<code>`.

Video score policy:

- Sample multiple frames uniformly.
- Analyze each sampled frame.
- Use the **maximum frame score** as video-level score.
